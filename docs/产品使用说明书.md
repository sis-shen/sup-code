 # 产品使用说明书
 
 ## 1. 简介
 
 SupCode 是一个终端原生的智能编程助手。把它装进你的终端，用自然语言告诉它想做什么，它会自己读代码、写文件、跑命令，把结果交给你。
 
 不绑定任何单一 AI 模型——你可以用 OpenAI、Claude、DeepSeek，也可以接本地模型。
 
 ---
 
 ## 2. 安装
 
 ### 方式 A：一键安装（推荐）
 
 ```bash
 # Linux / macOS
 curl -fsSL https://supcode.dev/install.sh | bash
 
 # Windows (PowerShell)
 irm https://supcode.dev/install.ps1 | iex
 ```
 
 ### 方式 B：包管理器
 
 ```bash
 # Go 开发者
 go install github.com/supcode/supcode/cmd/supcode@latest
 
 # Homebrew
 brew install supcode/tap/supcode
 
 # npm
 npm install -g supcode
 ```
 
 ### 方式 C：Docker
 
 ```bash
 docker pull supcode/supcode:latest
 docker run -v $(pwd):/workspace -e OPENAI_API_KEY=$OPENAI_API_KEY supcode "解释这个项目"
 ```
 
 ### 验证安装
 
 ```bash
 supcode --version
 # supcode v1.0.0 (go1.22, linux/amd64)
 ```

 ## 3. 快速开始
 
 ### 3.1 配置 API Key
 
 至少配置一个 LLM 供应商：
 
 ```bash
 supcode config set llm.provider openai
 supcode config set llm.api_key sk-your-key-here
 supcode config set llm.model 	deepseek-v4-flash
 ```
 
 或使用环境变量：
 
 ```bash
 export SUPCODE_LLM_PROVIDER=openai
 export SUPCODE_LLM_API_KEY=sk-your-key-here
 ```
 
 ### 3.2 第一次对话
 
 ```bash
 # 交互模式——进入 TUI
 supcode
 > 这个项目是做什么的？
 
 # 单次模式——直接执行
 supcode "帮我把 README.md 里的标题改成大写"
 ```
 
 ### 3.3 三个最常用的命令
 
 ```bash
 supcode                               # 进入交互模式
 supcode "你的需求描述"                  # 单次执行
 supcode config set llm.model gpt-4o    # 切换模型
 ```

 ## 4. 交互模式
 
 ### 4.1 界面布局
 
 ```
 +--------------------------------------------------+
 |  消息列表（可滚动）                                 |
 |                                                    |
 |  You:  帮我重构 utils.ts                            |
 |  Agent: 好的，我先看一下文件结构...                   |
 |  Agent: [Thinking... Glob **/*.ts]                |
 |  Agent: 找到 3 个文件，现在读取 utils.ts...            |
 |  Agent: 重构完成。修改了以下函数...                    |
 |                                                    |
 +--------------------------------------------------+
 | > _                                              |
 | [Ctrl+C 退出 | /help 帮助 | session: abc123]       |
 +--------------------------------------------------+
 ```
 
 ### 4.2 快捷键
 
 | 快捷键 | 操作 |
 |--------|------|
 | `Ctrl+C` | 退出程序 |
 | `Ctrl+D` | 退出当前会话 |
 | `Tab` | 自动补全（文件路径 / Slash 命令） |
 | `↑` / `↓` | 浏览历史消息 |
 
 ### 4.3 流式响应
 
 Agent 的回复是逐字出现的，你可以实时看到它在"思考"。当 Agent 正在调用工具时，界面会显示：
 
 ```
 Thinking... 正在读取 src/utils.ts
 ```
 
 调用完成后显示结果摘要。你可以在 Agent 输出过程中随时打断。

 ## 5. Slash Commands（斜杠命令）
 
 在交互模式中输入 `/` 查看所有可用命令：
 
 | 命令 | 说明 |
 |------|------|
 | `/new` | 开启新会话 |
 | `/clear` | 清空当前会话上下文 |
 | `/resume` | 恢复之前的会话 |
 | `/config` | 查看/修改配置 |
 | `/skills` | 列出已安装的技能包 |
 | `/mcp` | 管理 MCP 外部服务连接 |
 | `/exit` | 退出 SupCode |

 ## 6. 配置文件
 
 ### 6.1 配置优先级
 
 CLI 参数 > 环境变量 > 项目级配置 > 用户级配置 > 默认值
 
 ### 6.2 用户级配置
 
 `~/.supcode/config.yaml`：
 
 ```yaml
 llm:
   provider: openai
   model: gpt-4o
   api_key: ${OPENAI_API_KEY}
   max_tokens: 4096
 
 agent:
   max_iterations: 50
   permission_level: ask
 
 memory:
   project_memory_dir: .supcode/memory
   user_memory_dir: ~/.supcode/memory
 
 mcp:
   servers:
     - name: github
       command: npx
       args: ["-y", "@modelcontextprotocol/server-github"]
       env:
         GITHUB_PERSONAL_ACCESS_TOKEN: ${GITHUB_TOKEN}
 
 skills:
   auto_load:
     - "@supcode/skills-nodejs"
     - "./custom-skills/my-team-rules"
 ```
 
 ### 6.3 项目级配置
 
 在项目根目录创建 `.supcode/config.yaml`，内容同上。项目级配置里的 `llm.model` 会覆盖用户级的设置。

 ## 7. 权限控制
 
 SupCode 有五层安全防御，默认开启。你可以在配置中调整：
 
 ```yaml
 agent:
   permission_level: ask   # allow（全自动）/ ask（弹确认框）/ deny（只读）
 ```
 
 | 级别 | 行为 | 适用场景 |
 |------|------|---------|
 | `allow` | 所有操作自动执行，不弹确认 | 信任 Agent、快速原型 |
 | `ask` | 写操作和危险命令弹出确认框 | 日常开发（推荐） |
 | `deny` | 只允许读操作，拒绝写和命令执行 | 代码审查、探索未知项目 |
 
 ### 自定义权限规则
 
 ```yaml
 permission:
   rules:
     - scope: "path"
       pattern: "/etc/"
       decision: "deny"
     - scope: "command"
       pattern: "npm (publish|deploy)"
       decision: "ask"
     - scope: "tool"
       pattern: "bash"
       decision: "allow"
 ```

 ## 8. 切换 AI 模型
 
 ### OpenAI
 
 ```bash
 supcode config set llm.provider openai
 supcode config set llm.model gpt-4o
 supcode config set llm.api_key sk-xxx
 ```
 
 ### Anthropic Claude
 
 ```bash
 supcode config set llm.provider anthropic
 supcode config set llm.model claude-sonnet-4-20250514
 supcode config set llm.api_key sk-ant-xxx
 ```
 
 ### DeepSeek
 
 ```bash
 supcode config set llm.provider deepseek
 supcode config set llm.model deepseek-chat
 supcode config set llm.api_key sk-xxx
 ```
 
 ### 本地模型（Ollama）
 
 ```bash
 supcode config set llm.provider ollama
 supcode config set llm.model qwen2.5-coder:7b
 supcode config set llm.base_url http://localhost:11434/v1
 ```
 
 ### 多模型故障切换
 
 配置多个供应商后，当首选模型不可用时自动切换：
 
 ```yaml
 llm:
   providers:
     - openai
     - anthropic
     - deepseek
   fallback: true
 ```

 ## 9. Plan Mode
 
 在执行复杂任务前先让 Agent 出计划，你确认后再执行：
 
 ```bash
 supcode --plan "重构 auth 模块，拆分为 auth/login、auth/register、auth/middleware"
 ```
 
 界面会展示：
 
 ```
 计划：
   1. [ ] 分析 auth 模块当前结构
   2. [ ] 创建 auth/login 子包
   3. [ ] 创建 auth/register 子包
   4. [ ] 创建 auth/middleware 子包
   5. [ ] 迁移对应代码
   6. [ ] 更新 import 路径
   7. [ ] 运行测试验证
 
 [Y] 确认执行  [N] 重新规划  [E] 编辑计划
 ```

 ## 10. Skills（技能包）
 
 Skill 是预先打包好的 Prompt 模板 + 工具组合，让 Agent 拥有特定领域的专业能力。
 
 ### 查看已安装的 Skill
 
 ```bash
 supcode skill list
 ```
 
 ### 安装 Skill
 
 ```bash
 # 从本地目录安装
 supcode skill install ./my-custom-skill
 
 # 从 Git 仓库安装
 supcode skill install https://github.com/user/supcode-skill-review
 
 # 从 npm 安装
 supcode skill install @supcode/skill-python
 ```
 
 ### 卸载
 
 ```bash
 supcode skill uninstall skill-name
 ```
 
 ### 编写自己的 Skill
 
 创建一个目录，放入以下文件：
 
 ```
 my-skill/
   skill.json              # 元数据
   prompts/system.md       # 系统提示词模板
 ```
 
 `skill.json`：
 
 ```json
 {
   "name": "my-code-review",
   "version": "1.0.0",
   "description": "按我团队的规范审查代码",
   "author": "your-name",
   "tools": ["readfile", "grep", "bash"]
 }
 ```
 
 `prompts/system.md`：
 
 ```markdown
 你是一个代码审查专家。审查时请关注：
 1. 函数长度不超过 50 行
 2. 错误处理是否完整
 3. 是否有潜在的性能问题
 ```

 ## 11. MCP 外部工具
 
 MCP（Model Context Protocol）让 SupCode 可以接入 GitHub、Slack、数据库等外部服务。
 
 ### 接入 GitHub MCP Server
 
 ```yaml
 # ~/.supcode/config.yaml
 mcp:
   servers:
     - name: github
       command: npx
       args: ["-y", "@modelcontextprotocol/server-github"]
       env:
         GITHUB_PERSONAL_ACCESS_TOKEN: ${GITHUB_TOKEN}
 ```
 
 配置后，SupCode 启动时会自动连接。Agent 可以直接查询 Issue、创建 PR：
 
 ```
 > 帮我查一下这个项目的 open issues，看看有没有关于 login 页面的 bug
 ```

 ## 12. SubAgent 并行工作
 
 当任务可以被拆分为独立子任务时，SupCode 会自动并行处理：
 
 ```
 > 给 src/ 下所有 .go 文件添加 Apache 2.0 许可证头
 
 Agent: 找到 12 个 .go 文件，启动 3 个子 Agent 并行处理...
 Agent: [SubAgent 1] 处理完毕 4 个文件
 Agent: [SubAgent 2] 处理完毕 4 个文件
 Agent: [SubAgent 3] 处理完毕 4 个文件
 Agent: 全部完成！
 ```
 
 你可以配置并行数量：
 
 ```yaml
 agent:
   max_sub_agents: 4
 ```

 ## 13. 常见场景速查
 
 ```bash
 # 代码生成
 supcode "在 src/api/ 下创建一个 RESTful 用户管理模块，包含 CRUD 接口和 Swagger 注解"
 
 # 代码重构
 supcode "把 utils.ts 里所有的 any 类型改成具体类型"
 
 # Bug 修复
 supcode "运行测试然后修复所有失败的用例"
 
 # 代码审查
 supcode "审查最近 3 个 commit 的变更，列出潜在问题"
 
 # 项目分析
 supcode "分析这个项目的模块依赖关系，画一个架构图"
 
 # 文档生成
 supcode "为所有公开函数生成 godoc 注释"
 
 # 依赖管理
 supcode "把过期的 npm 依赖升级到最新版本，然后跑测试确认没问题"
 ```

 ## 14. 故障排查
 
 | 问题 | 解决方法 |
 |------|---------|
 | `api_key not configured` | `supcode config set llm.api_key sk-xxx` 或设置环境变量 |
 | Agent 不写文件 | 检查 `permission_level` 是否为 `deny`，改为 `ask` |
 | 响应很慢 | 切换到更快的模型（如 `gpt-4o-mini`），或使用本地 Ollama |
 | 上下文丢失 | 长对话会自动压缩，输入 `/new` 开启新会话重新开始 |
 | MCP 服务连不上 | `supcode mcp list` 查看状态，确认外部服务的 token 有效 |
